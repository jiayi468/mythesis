| 浏览器预处理 | Python↔Canvas 输入 MAE `0.00603`；分数误差 `0.018327` | 未对齐前不得开展正式端到端精度和性能宣传 |

### 1.2 当前结论边界

1. 当前仍是 MVTec AD `pill`、`screw` 两类源域监督开发实验，不是官方无监督协议或跨数据集零样本结果。
2. Oracle ROI 使用真实掩膜定位，只证明局部放大存在上界价值，不证明模型能自动找到缺陷。
3. B2 的图像级优势不足以证明文本原型具有跨数据集泛化优势；B1 必须继续作为公平对照。
4. max 聚合是在同一验证集上观察到的结果，需经独立开发集冻结后才能用于正式测试。
5. WebGPU 当前只能证明固定张量后端一致，不证明浏览器图像链路一致或获得加速。

## 二、下一阶段目标与研究问题

### 2.1 总体目标

构建并验证一条不依赖 GT 的自动粗到细推理链路：由全图 `224×224` 粗异常图生成少量候选区域，在固定计算预算下完成局部高分辨率重编码，并评估候选召回、定位收益、误报漂移和 WebGPU 实际延迟。

### 2.2 研究问题

#### RQ1：粗异常图能否自动找到值得放大的区域？

- 比较 Top-K Patch、局部峰值、连通区域和 NMS 候选。
- 核心指标为 `Region Recall@K`，而不是只看最终 AUROC。
- 必须同时与 Random ROI 和 Oracle ROI 比较。

#### RQ2：固定 K 自动 ROI 能否获得稳定精度收益？

- 比较 `K=0/1/2/4`。
- 观察 Pixel AP、微小缺陷召回、正常样本误报和每张图额外推理次数。
- 自动 ROI 的收益必须在多个种子和两个类别上稳定，而非来自少量案例。

#### RQ3：M1 训练是否能改善候选有效性？

- 对比当前全图训练与全图/ROI 联合训练。
- 缺陷保持监督已经使用 Max-Pooling，下一步重点验证 ROI 训练分布适配，而不是重复证明 Max-Pooling 本身。
- 只有简单候选召回不足时才加入区域排序损失。

#### RQ4：动态 K 是否优于固定 K？

- 使用设备实测增量延迟表选择 K。
- 比较固定 K、简单风险阈值动态 K、无设备成本动态 K 和设备感知动态 K。
- 必须检查 K 增大导致的正常样本分数漂移和误报上升。

#### RQ5：自动粗到细链路能否在浏览器稳定运行？

- 先解决 Python/Canvas 预处理不一致。
- 再测 `B=1` 顺序 ROI 和动态 Batch `B=1/2/4`。
- 报告端到端 P50/P95、初始化、预处理、模型前向、融合和资源占用。

## 三、固定实验协议

### 3.1 数据与模型

- 开发数据继续使用当前 `pill`、`screw` 冻结清单，不改变训练/验证划分。
- 训练种子继续使用 `42、123、2026`。
- 主干固定为冻结 CLIP ViT-B/16，输入 `224×224`，Patch 网格 `14×14`。
- B1 普通分类头和 B2 文本原型头均保留；自动候选实验优先使用 B2，同时用 B1 检查候选收益是否依赖文本原型。
- 损失固定为 `Focal Loss + Dice Loss`。
- ROI 与全图共享同一模型，不训练独立局部模型。

### 3.2 候选与融合

- ROI 上下文扩展比例首先固定为 Oracle 实验使用的 `25%`。
- K 固定比较 `0、1、2、4`。
- 候选去重首先使用基于框 IoU 的 NMS，阈值固定为 `0.3`。
- ROI 热力图回投后与全图热力图使用逐像素最大值融合。
- 图像级分数在聚合协议冻结前继续使用 `99.5%` 分位数；max 只作为诊断分支。
- 不依据目标域结果改变 ROI 尺寸、NMS 阈值、K 或融合规则。

### 3.3 缺陷尺度分组

按原图掩膜面积比例在源域开发集冻结 Tiny/Small/Medium 分组阈值。阈值只根据源域掩膜面积分布确定，并写入配置；正式目标域只应用已冻结阈值，不重新分组调参。

### 3.4 评价指标

候选阶段：

- Region Recall@1、@2、@4；
- GT 覆盖率；
- 候选框平均数量、平均面积和重复率；
- Tiny/Small 子集召回；
- Random ROI、简单 Top-K 和 Oracle 上界之间的距离。

最终检测阶段：

- Image AUROC、Image AP；
- Pixel AUROC、Pixel AP；
- Tiny/Small 子集 Pixel AP 和召回；
- 正常样本分数均值、P95、P99；
- K 变化导致的正常样本误报率；
- 每类、合并集合、每个种子和均值±标准差。

部署阶段：

- 模型加载、首次推理、预热后 P50/P95；
- 全图预处理、全图模型、候选生成、ROI 裁剪、ROI 模型、融合、渲染的分段耗时；
- K=0/1/2/4 的端到端时间；
- 动态 Batch 与顺序 `B=1` 的时间及失败率；
- 浏览器、GPU、驱动、分辨率、运行轮数和热身轮数。

## 四、实验阶段与执行任务

## 阶段 A：自动候选生成与 Region Recall@K

### A1. 实现候选生成器

从 `14×14` 粗异常图实现三种低成本候选：

1. **Patch Top-K：** 直接选择最高分 Patch，并映射到原图区域；
2. **局部峰值 + NMS：** 先做局部最大值筛选，再按 IoU 去重；
3. **阈值连通区域：** 使用源域冻结阈值形成连通区域，并按区域最大值排序。

必须保留两个参照：

- Random ROI：同 K、同尺寸分布、固定随机种子；
- Oracle ROI：现有 GT 上界结果。

### A2. 候选召回实验

对 B1、B2 三个训练种子分别计算：

| 方法 | K | Region Recall@K | Tiny Recall@K | GT 覆盖率 | 候选重复率 |
|---|---:|---:|---:|---:|---:|
| Random | 1/2/4 | 实测 | 实测 | 实测 | 实测 |
| Patch Top-K | 1/2/4 | 实测 | 实测 | 实测 | 实测 |
| 峰值+NMS | 1/2/4 | 实测 | 实测 | 实测 | 实测 |
| 连通区域 | 1/2/4 | 实测 | 实测 | 实测 | 实测 |
| Oracle | 1 | 1.0 | 1.0 | 1.0 | 0 |

### A3. 阶段验收门

进入自动 ROI 重编码的最低条件：

- 至少一种简单方法的 Region Recall@4 在两个类别上均明显高于 Random；
- `pill`、`screw` 均至少有 2/3 个种子达到正向结果；
- Tiny 子集不是完全失效；
- 候选生成 CPU 开销相对一次模型前向可忽略。

若未通过：停止动态 K，直接进入阶段 C 的 M1 候选保持训练。

## 阶段 B：固定 K 自动粗到细验证

### B1. 固定 K 实验矩阵

对通过阶段 A 的最佳简单候选方法运行：

```text
Head：B1、B2
Seed：42、123、2026
K：0、1、2、4
Fusion：max
ROI context：25%
```

主表必须同时报告：

- Full-224；
- Full + Random ROI；
- Full + 自动 ROI；
- Full + Oracle ROI。

### B2. 正常样本分数漂移

对每个 K 统计正常样本：

- 图像分数均值、标准差、P95、P99；
- 相对 K=0 的分数增量；
- 使用源域冻结阈值时的误报率；
- ROI 最大融合是否造成“看得越多，异常分数必然越高”。

如果正常样本分数随 K 单调明显升高，增加以下固定校准对照：

1. K 条件分位数校准；
2. 全图分数与 ROI 分数分别归一化后融合；
3. 图像级分数保持全图分支，ROI 只更新像素热力图。

三者只在源域开发集选择一次，随后冻结。

### B3. 阶段验收门

进入动态 K 的条件：

- 自动 ROI 在至少一个 K 上使合并 Pixel AP 平均提高不少于 `0.02`；
- 两个类别的平均增量均为正，且多数种子方向一致；
- 自动 ROI 明显优于 Random ROI；
- 自动结果达到 Oracle 增量的至少 40%；
- 正常样本误报没有出现不可校准的明显恶化。

未通过时：

- 候选召回高但重编码无收益：检查 ROI 尺度、上下文和训练分布；
- 候选召回低：进入阶段 C；
- 仅 `pill` 有效：保留类别差异结论，不直接启动通用动态 K。

## 阶段 C：M1 全图/ROI 联合训练

### C1. 训练样本构成

从源域训练图生成：

- 低分辨率全图；
- 覆盖异常的正 ROI；
- 邻近异常但不覆盖缺陷的难负 ROI；
- 正常图随机 ROI。

先固定采样比例：

```text
全图 : 正 ROI : 难负 ROI : 正常 ROI = 2 : 1 : 1 : 1
```

仅当训练不稳定或某类样本完全无效时，才在源域验证中调整一次并记录原因。

### C2. 最小消融

| 编号 | 缺陷保持监督 | ROI 联合训练 | 区域排序损失 | 用途 |
|---|---|---|---|---|
| M0 | 当前 Max-Pooling | 否 | 否 | 当前基线 |
| M1-a | 当前 Max-Pooling | 是 | 否 | 验证尺度分布适配 |
| M1-b | 普通面积下采样 | 是 | 否 | 检查缺陷保持监督作用 |
| M1-c | 当前 Max-Pooling | 是 | 是 | 仅候选排序仍不足时运行 |

优先完成 M0、M1-a、M1-b。M1-c 不是默认必做项。

### C3. 训练验收门

M1-a 至少应满足一项：

- Region Recall@K 相对 M0 稳定提高；
- Tiny/Small Pixel AP 提高；
- 固定 K 自动 ROI 最终 Pixel AP 提高；
- 在不降低 Full-224 结果的情况下缩小自动 ROI 与 Oracle 的差距。

若 M1-a 无收益，不继续叠加排序损失，优先检查所选 CLIP 特征层和 ROI 尺度。

## 阶段 D：浏览器预处理对齐与固定 K 性能测试

### D1. 预处理对齐

按以下顺序定位差异：

1. 固定 RGB/Alpha 和 NCHW 排列；
2. 核对 PIL Bicubic 与 Canvas `drawImage` 插值；
3. 比较 resize 后、归一化前的逐像素值；
4. 比较归一化后的输入张量；
5. 比较 ONNX CPU 与 WebGPU 输出。

通过标准：

- Python↔浏览器输入张量 MAE ≤ `1e-3`；
- 图像路径异常分数误差 ≤ `1e-3`；
- 固定张量 ONNX CPU↔WebGPU 误差继续 ≤ `1e-4`。

半天内无法对齐时，采用显式 JavaScript Bicubic 实现或预先缩放的实验输入；必须记录实现，不以 Canvas 默认行为代替一致协议。

### D2. 固定 K 性能表

至少在 AMD 集显和 NVIDIA 独显设备分别测：

| 设备 | 执行方式 | K | P50 | P95 | 失败率 | 备注 |
|---|---|---:|---:|---:|---:|---|
| AMD 集显 | 顺序 B=1 | 0/1/2/4 | 实测 | 实测 | 实测 | 必做 |
| AMD 集显 | 动态 Batch | 1/2/4 | 实测 | 实测 | 实测 | 支持则做 |
| NVIDIA 独显 | 顺序 B=1 | 0/1/2/4 | 实测 | 实测 | 实测 | 必做 |
| NVIDIA 独显 | 动态 Batch | 1/2/4 | 实测 | 实测 | 实测 | 支持则做 |

每个条件至少预热 5 次、正式运行 30 次。动态 Batch 不稳定时回退顺序 `B=1`，不维护多套权重。

## 阶段 E：设备感知动态 K

### E1. 固定对照

1. 固定 K=0；
2. 固定 K=1；
3. 固定 K=2；
4. 固定 K=4；
5. 简单风险阈值动态 K；
6. 不使用设备成本的收益排序；
7. 使用设备增量延迟表的动态 K。

### E2. 最小策略

候选区域按粗图异常风险排序。对于第 k 个候选，只有当源域估计收益超过设备实测增量成本对应的停止阈值时才继续；阈值在源域验证集冻结。首版不使用额外学习网络。

### E3. 评价方式

- 绘制 Pixel AP—P50、Pixel AP—P95 Pareto 图；
- 报告每种策略的平均 K、K 分布和正常/异常样本 K 分布；
- 检查是否只对高分正常样本分配更多 ROI；
- 分别在 AMD 和 NVIDIA 设备形成成本表，不跨设备复用延迟参数。

### E4. 成功标准

设备感知动态 K 必须至少满足：

- 在相近 Pixel AP 下延迟低于固定 K；或
- 在相近延迟下 Pixel AP 高于固定 K；
- 优势在至少一台设备上形成非支配 Pareto 点；
- 相对简单风险阈值有可解释增益；
- 未显著提高正常样本误报。

若不满足，则论文只保留固定 K 的精度—成本分析，不把动态 K 写成已验证贡献。
