# 中期最低线实验实施计划

日期：2026-10-16

## 一、实施目标

在当前 Windows CPU 环境中完成 `pill`、`screw` 两类 MVTec AD 数据的真实源域开发实验，形成可复现的数据划分、CLIP ViT-B/16 Patch 特征缓存、轻量异常头训练、指标与热力图、静态 ONNX 导出及 PyTorch/ONNX CPU 一致性证据。

实验结论统一标注为“源域小样本探索性验证”。WebGPU 为条件性加分项，不阻塞 CPU 最低线。

## 二、固定技术选择

- Python 3.10，PyTorch CPU。
- 主干：OpenAI 预训练 CLIP ViT-B/16，完全冻结。
- 输入：RGB `224×224`，CLIP 标准归一化。
- 特征：最后一层 Transformer 的 `14×14` Patch Token。
- 异常头：两层 MLP，输出每个 Patch 的二分类 logits。
- 文本原型：使用固定对象无关 Prompt 离线生成；本轮保留原型和相似度输出用于诊断，异常头训练不依赖目标类别名称。
- 标签：异常掩膜以自适应最大池化降到 `14×14`。
- 损失：二分类 Focal Loss 与 Dice Loss 之和。
- 图像分数：Patch 异常概率的 `99.5%` 分位数。
- 随机种子：42。
- 源域异常样本按类别和缺陷类型确定性分层为 70% 训练、30% 验证；原始 `test/good` 全部作为正常验证，原始 `train/good` 确定性抽样组成正常训练集。

## 三、阶段与验收

### 阶段 1：工程骨架与数据协议

1. 增加 `.gitignore`，排除数据集、缓存、权重、ONNX 和运行日志大文件。
2. 建立 Python 包、配置文件、命令行脚本和测试目录。
3. 先编写数据发现、图像—掩膜配对、固定划分和路径无交集测试。
4. 实现数据审计并生成 `midterm/experiments/source_split.csv`。

验收：两类数据全部可读，260 张异常图均有掩膜，固定种子重复运行得到同一清单，训练/验证不重叠。

### 阶段 2：预处理、特征和缓存

1. 先测试 RGB 转换、CLIP 归一化、输出 shape 和缺陷保持掩膜下采样。
2. 实现 CLIP ViT-B/16 Patch Token 提取与固定文本原型生成。
3. 实现带模型、预处理和源文件元数据的缓存格式。
4. 用极小样本完成真实 CLIP 前向冒烟测试，再缓存受控实验子集。

验收：获得真实 `[N,196,D]` Patch 特征，非空微小掩膜下采样后仍非空，缓存可重复加载且元数据一致。

### 阶段 3：异常头训练与评测

1. 先测试模型输出、冻结参数、Focal/Dice 损失和人工指标样例。
2. 实现轻量异常头、训练循环、早停和 checkpoint。
3. 首先运行小样本冒烟训练；确认 Loss 可反向传播后运行受控正式实验。
4. 计算 Image AUROC、Image AP、Pixel AUROC、Pixel AP，并按类别及合并集合输出。

验收：保存配置、日志、checkpoint、`results.csv`；指标来自真实数据且标明样本范围。

### 阶段 4：可视化与失败案例

1. 生成原图、GT、预测热力图和叠加图。
2. 保存正常、明显异常、微小异常以及至少一个高分误报或低分漏检案例。
3. 图注包含类别、缺陷类型、相对路径、标签和预测分数。

验收：输出可直接用于中期答辩的真实证据图，不生成模拟热力图。

### 阶段 5：ONNX 与一致性

1. 将视觉主干、异常头和图像评分包装成静态 B=1 模型。
2. 导出 `image -> anomaly_map, image_score`。
3. 运行 ONNX checker 和 ONNX Runtime CPU。
4. 固定若干验证输入，记录最大绝对误差、平均绝对误差和分数排序。

验收：成功时保存模型及对照 CSV；失败时保存完整导出命令、错误和最小复现日志。

### 阶段 6：WebGPU 条件性验证

仅在 ONNX CPU 一致性通过后执行。页面使用 ONNX Runtime Web 的 WebGPU execution provider，展示输入图像、异常分数、热力图、后端、首次推理和预热时延。若浏览器自动化不能核实后端，则保留为“未开展”并提供人工复现步骤，不将 WASM 结果冒充 WebGPU。

## 四、受控 CPU 实验规模

为在 CPU 环境内优先形成真实证据，第一次正式运行固定为：

- 每类异常训练样本最多 48 张；
- 每类正常训练样本最多 48 张；
- 每类异常验证样本最多 32 张；
- 每类正常验证使用原始 `test/good`，最多 32 张；
- 每个缺陷类型至少保留一个验证样本；
- Batch Size 由一次前向基准确定，默认从 4 开始；
- 异常头最多训练 30 Epoch，以验证 Loss 早停。

该规模只用于中期最低线。若运行耗时可接受，再扩展到完整固定划分，不覆盖小规模结果和日志。
