## 一、当前状态与本轮目标

### 1.1 已有基础

当前已经具备以下真实证据：

- 冻结 CLIP ViT-B/16 的 `14×14` Patch 特征提取链路；
- Adapter 与固定正常/异常文本原型组成的 Patch 异常检测头；
- `pill`、`screw` 两类共 96 张样本的固定训练/验证清单；
- 图像级和像素级指标、热力图及失败案例；
- 静态 `B=1` ONNX 导出和 PyTorch/ONNX CPU 一致性验证；
- Chrome WebGPU 真实前向、截图和时延记录；
- 18 项自动化测试通过。

当前结果属于**源域小样本监督开发验证**，不是标准 MVTec AD 无监督基准，也不是正式跨数据集零样本结果。现有主要不足为：

1. PPT、讲稿、答辩问答尚未完成，整个中期答辩最低线尚未完全闭环；
2. 每类验证样本只有 16 张，指标方差和偶然性较大；
3. 尚未证明固定 CLIP 文本原型相对普通分类头具有实际价值；
4. 尚未验证 Oracle ROI 是否能提高微小缺陷检测上界；
5. 浏览器 Canvas 预处理与 Python 预处理仍存在输出差异；
6. 当前结果不能与采用不同监督条件、类别范围和数据划分的论文数值直接排名。

### 1.2 本轮总体目标

未来 2～3 天不追求完整 M1/M2，而是完成以下四个目标：

1. **补齐答辩材料：** 完成 PPT、讲稿、问答、状态表和离线证据；
2. **提高实验可信度：** 扩大两类受控样本，运行多随机种子并报告波动；
3. **建立公平对照：** 比较纯 CLIP、普通分类头和当前文本原型头；
4. **验证核心路线：** 通过 Oracle ROI 判断粗到细和局部放大是否值得继续。

浏览器预处理对齐、官方 WinCLIP 参考运行和第三类别属于条件性加分项，不得挤占上述核心任务。

## 二、执行原则与结果口径

### 2.1 三类结果必须分开

| 结果类型 | 含义 | 是否可直接与当前结果排名 |
|---|---|---|
| 论文报告结果 | 从原论文或官方附录抄录，采用论文自身协议 | 否，只用于相关工作背景 |
| 官方方法参考运行 | 使用官方代码，在本项目固定图像清单上推理 | 条件性可以，但必须说明复现差异 |
| 本项目内部对照 | 使用相同数据、特征、划分、指标和训练预算 | 可以，是本轮主要定量证据 |

论文数字与当前结果同时出现时，必须明确标注：

> 论文报告结果与本项目的监督信息、类别范围和数据划分不同，仅用于背景参考，不构成直接性能排名。

### 2.2 禁止的比较方式

- 不把当前两类、32 张验证图像的合并结果与 MVTec AD 15 类宏平均直接比较；
- 不把使用源域异常掩膜训练的结果称为标准无监督 MVTec AD 结果；
- 不将 Pixel AUROC、Pixel AP、AU-PRO 等不同指标互相替代；
- 不只选择 `pill` 的较好结果而隐藏 `screw` 的失败；
- 不把论文原文数字写成“本项目复现结果”；
- 不依据验证结果反复改变 Prompt、阈值或划分后只报告最好一次；
- 不使用“超过 SOTA”“显著领先”等缺乏同协议证据的表述。

### 2.3 本轮固定结论边界

- 当前训练允许使用源域异常图像和掩膜；
- “零样本”只保留为后续目标域零训练、零调参、零阈值校准的研究目标；
- 本轮结果用于检验基础模型、文本原型和 ROI 上界，不证明最终跨数据集泛化；
- WebGPU 当前只能证明兼容性和真实执行，不能声称获得加速。

## 四、扩展实验协议

### 4.1 数据划分

保留当前 96 张小实验及其全部日志，不覆盖、不重命名。新增扩展实验采用独立配置和输出目录。

建议的扩展上限如下：

| 类别 | 正常训练 | 异常训练 | 正常验证 | 异常验证 |
|---|---:|---:|---:|---:|
| pill | 最多 48 | 最多 48 | 使用原始 `test/good` 全部 26 张 | 最多 32 |
| screw | 最多 48 | 最多 48 | 固定抽取 32 张 | 最多 32 |

具体要求：

- 延续确定性划分，不允许训练和验证路径重叠；
- 异常样本按缺陷类型分层，各缺陷类型尽量进入验证集；
- 数据划分只生成一次，三个训练种子共用同一清单；
- 建议训练种子使用 `42、123、2026`；
- CLIP Patch 特征按文件哈希和预处理配置缓存，避免每个种子重复提取；
- 扩展实验结果与当前小实验分别保存。

### 4.2 固定评价指标

每个类别和合并集合均报告：

- Image AUROC；
- Image AP；
- Pixel AUROC；
- Pixel AP；
- 最佳验证 Loss 与最佳 Epoch；
- 三个种子的均值、标准差和单次结果；
- 可训练参数量；
- 正常、明显异常、微小异常、误报和漏检案例。

Pixel AUROC 必须与 Pixel AP 同时解释。合并指标不能替代逐类别指标。

### 4.3 图像级分数聚合诊断

为分析 `screw` 图像级 AUROC 偏低的问题，在不重新训练的前提下固定比较：

- Patch 最大值；
- 当前 `99.5%` 分位数；
- Top-k Patch 均值，其中 k 在实验前固定，不根据结果反复搜索。

该实验属于评分聚合诊断。若需要选择最终聚合方式，应使用独立开发集；本轮不得在同一验证集上选择最好方式后将其作为无偏结果。

## 五、三组公平基线

### 5.1 B0：纯 CLIP 文本相似度

```text
冻结 CLIP Patch 特征
    ↓
固定正常/异常文本原型
    ↓
余弦相似度与 Softmax
    ↓
异常图和图像分数
```

目的：检验原始 CLIP Patch 表征是否直接包含可用的异常语义。该基线不使用异常掩膜训练，因此不与有监督头宣称完全公平，只作为能力下界和语义诊断。

### 5.2 B1：普通可学习二分类头

```text
冻结 CLIP Patch 特征
    ↓
与当前方法相同规模的 Adapter
    ↓
可学习二分类权重
    ↓
异常图和图像分数
```

目的：检验当前效果是否主要来自异常掩膜监督，而不是固定文本语义。

公平性要求：

- 与当前方法使用相同输入特征、隐藏维度、Dropout、损失、优化器、学习率、Batch Size、Epoch 和早停条件；
- 参数量尽量匹配，无法完全相同时必须报告差异；
- 不为某一个基线单独调参。

### 5.3 B2：当前文本原型头

```text
冻结 CLIP Patch 特征
    ↓
可训练 Adapter 映射至 CLIP 文本空间
    ↓
固定正常/异常文本原型
    ↓
异常图和图像分数
```

目的：作为当前方法基线，判断固定文本原型相对普通二分类权重是否带来稳定收益。

### 5.4 验收表

| 基线 | 数据划分 | 训练种子 | 参数量 | Image AUROC/AP | Pixel AUROC/AP | 结论 |
|---|---|---|---:|---|---|---|
| B0 纯 CLIP | 固定扩展清单 | 不适用 | 0 | 实测 | 实测 | 原始语义能力 |
| B1 普通分类头 | 固定扩展清单 | 3 | 实测 | 均值±标准差 | 均值±标准差 | 监督学习对照 |
| B2 文本原型头 | 固定扩展清单 | 3 | 实测 | 均值±标准差 | 均值±标准差 | 当前方法 |

结论只允许写成：

- 文本原型头在当前源域开发协议下表现更好、相近或更差；
- 是否稳定必须结合三个种子和两个类别判断；
- 即使 B2 优于 B1，也不能据此证明跨数据集泛化更强。

## 七、Oracle ROI 上界实验

### 7.1 实验目的

Oracle ROI 只回答：将真实缺陷区域从原始高分辨率图像中放大后，当前模型是否获得更好的异常响应。它不代表可部署方法，也不证明候选区域可以由模型自动找到。

### 7.2 固定流程

```text
验证图像及 GT 掩膜
    ↓
在原始分辨率上计算缺陷外接框
    ↓
按固定比例扩展上下文并裁剪
    ↓
ROI 缩放至 224×224
    ↓
使用同一 CLIP 与异常头推理
    ↓
映射回原图并与全图结果比较
```

最低实现为 Oracle-1：使用覆盖全部异常像素的最小外接框，并在四周增加固定比例上下文。只有 Oracle-1 获得稳定正向结果后，才考虑 Oracle-2 或多个连通域。

### 7.3 对照组

- Full-224：当前全图输入；
- Oracle-1：单个真实缺陷 ROI；
- Full + Oracle-1：固定融合规则；
- 可选 Random ROI：相同尺寸的随机区域，用于排除单纯放大带来的偶然收益。

### 7.4 输出与判定

至少输出：

- 每类 Image AUROC/AP、Pixel AUROC/AP；
- 微小缺陷子集结果；
- 全图、GT、ROI 框、ROI 热力图和融合图；
- 每张图的全图分数与 ROI 分数；
- ROI 数量和额外推理次数。

Go/No-Go 原则：

| 现象 | 决策 |
|---|---|
| Oracle ROI 在多个种子/类别上稳定改善 Pixel AP 或微小缺陷案例 | 继续实现 Top-K、NMS 和 Region Recall@K |
| 仅个别样本改善，整体波动较大 | 记录为现象观察，不进入动态 K |
| Oracle ROI 无改善或明显退化 | 暂停粗到细路线，优先改进特征层与缺陷保持训练 |
| Oracle 有效但自动候选召回低 | 后续 M1 聚焦候选保持和粗阶段召回 |

## 八、WebGPU 预处理一致性补充

### 8.1 当前问题

固定 Python float32 张量输入时，ONNX CPU 与 WebGPU 分数基本一致；但浏览器 Canvas 直接读取同一图像时，分数与 Python 结果相差约 `0.0183`。因此当前部署结论只能证明模型后端一致，尚未证明浏览器图像预处理完全一致。

### 8.2 检查顺序

1. 核对 RGB 通道顺序和 Alpha 通道处理；
2. 核对 resize、中心裁剪或直接拉伸规则；
3. 核对 Canvas 插值行为与 Python 插值模式；
4. 核对像素除以 255 的位置和 float32 转换；
5. 核对 CLIP mean/std、NCHW 排列和内存顺序；
6. 导出同一图像的浏览器预处理张量，与 Python 张量逐元素比较；
7. 再比较 ONNX CPU 和 WebGPU 输出。

### 8.3 验收记录

记录输入张量最大绝对误差、平均绝对误差，输出热力图最大/平均绝对误差以及异常分数误差。若半天内不能达到预设一致性阈值，则保留现状和误差来源，不开展 WebGPU 性能优化。

## 十二、风险与回退

| 风险 | 处理方式 | 回退结论 |
|---|---|---|
| 扩展样本 CPU 特征提取过慢 | 先完成两类较小扩展，复用缓存 | 报告规模限制，不伪造完整结果 |
| 三个种子波动较大 | 如实报告均值、标准差和单次结果 | 当前基线不稳定，后续先改善训练 |
| 普通分类头优于文本原型头 | 检查参数量与训练公平性 | 收缩多模态贡献，文本原型作为待改进组件 |
| 纯 CLIP 表现很差 | 记录为语义与局部缺陷存在鸿沟 | 强调 Adapter 和源域监督必要性 |
| Oracle ROI 无收益 | 停止 Top-K 和动态 K | 转向缺陷保持或多层特征融合 |
| WinCLIP 环境无法运行 | 半天止损并保存日志 | 使用协议对照，不宣称完成复现 |
| 浏览器预处理难以完全对齐 | 保留固定张量后端一致性证据 | 不进行性能宣传，只报告兼容边界 |
| 材料制作时间不足 | 取消 P3 和所有新类别 | 优先 PPT、讲稿、问答和真实证据 |

## 十四、本轮结束后的决策

本轮结束时必须形成书面决策，不无限增加实验：
