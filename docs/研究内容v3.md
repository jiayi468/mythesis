## 一、研究定位与目标

### 1.1 论文题目

**基于 WebGPU 的工业多模态异常检测方法**

### 1.2 研究动机

工业图像异常往往具有**局部性、稀疏性及尺度差异大**等特点。视觉语言模型有望利用正常/异常语义实现跨类别与跨数据集异常检测，但在低分辨率推理时，微小缺陷可能被缩放和 Patch 特征聚合削弱；若直接对整张图像采用高分辨率编码，计算与内存负担又可能过高。

浏览器 WebGPU 为跨平台、免专用运行环境的端侧推理提供条件，同时也对模型尺寸、图像尺寸、数据传输和运行时延迟提出约束。**浏览器端不是为了证明其一定比本地原生推理快；研究目标是寻找其受限计算条件下可验证的精度—成本权衡。**

### 1.3 核心科学/技术问题

> 在不使用目标域样本训练、调参或校准的前提下，能否让轻量视觉语言异常检测模型先以低分辨率获得高召回的异常候选，再按设备实测计算成本选择少量高分辨率局部观察，从而在浏览器 WebGPU 中改善微小缺陷检测效果与实际推理延迟之间的权衡？

### 1.4 研究目标

1. **可复现基线**：完成 CLIP 系列轻量视觉语言异常检测的 PyTorch 训练/测试、ONNX 导出、浏览器 WebGPU 推理与热力图可视化。
2. **算法目标 M1**：在固定学生模型规模的条件下，改善低分辨率粗阶段对微小缺陷区域的召回，提高有限 ROI 预算下的候选有效性。
3. **算法目标 M2**：使用可解释、低开销的区域收益评分与设备实测延迟表，动态决定局部细化的数量，验证相对固定计算分配的收益。
4. **系统目标**：实现完整的无服务端推理浏览器系统，并报告精度、端到端延迟、初始化、稳定性、资源占用与失败案例。

上述目标的实质是**在端侧计算约束下进行任务感知的计算分配**，而不是重复实现一个网页异常检测界面。

### 1.5 与已有研究的差异化定位（v3 补充）

以下为**截至 2026-10-16 的初步相关工作核查**，用于确定研究边界；不是已经完成的系统性文献综述，也不意味着任何方法已经在相同协议下复现。

2. 文献设定不同，**论文报道的精度不能直接横向比较**。正式定量对比只使用可获得的官方实现、能够匹配训练/目标域协议且输入及评测规则一致的方法；其余文献做方法差异分析。
3. 必须检查是否存在已有研究已同时考虑“目标域零训练、微小缺陷候选召回、WebGPU 端到端延迟、设备感知动态 ROI”。如有高度同构工作，收缩或修改创新主张，并将真正不同的实测机制作为研究重点。
4. 文献核查是**论文写作与基线选择任务**，不新增一条算法研发主线；第 1 个月整理文献对照表，第 5 个月随正式论文完成更新。

## 三、研究问题与可证伪假设

### RQ1：浏览器端基础推理是否可行？

以固定 224 输入，将 ViT-B/16 的全局及 Patch 异常分数从 PyTorch 迁移到 WebGPU，能否稳定运行并维持足够一致的输出？

- **验证**：模型转换成功率、算子支持、参考输出误差、异常排序一致性、P50/P95、初始化时间及内存。
- **风险**：模型导出/位置编码/显存或浏览器后端不兼容。

### RQ2：低分辨率粗阶段是否具有可恢复的局部信息？

- **H1（局部细化价值）**：对至少部分微小缺陷，原图 ROI 裁剪再编码优于全图低分辨率观察。
- **H2（候选可找回）**：仅用粗图的简单 Top-K + 去重，能够有效覆盖一部分真实缺陷区域，且优于随机选择。

> **关键限制**：缺陷保持标签聚合只能避免监督标签消失，不能凭空恢复已在 224 输入中消失的视觉信息。必须用 Oracle 与真实候选两层实验分别验证“局部有效”与“能够找对局部”。

### RQ3：端侧自适应计算分配是否值得研究？

- **H3（设备成本收益）**：在某些设备/精度区间中，少量 ROI 的端到端 WebGPU 延迟及资源需求能形成可用的 Pareto 权衡点。
- **H4（动态决策收益）**：相对固定 K、简单风险阈值和无设备感知的动态 K，考虑实测增量延迟的选择策略能更有效分配局部计算。

若 H1 或 H3 不成立，**不得把“微小缺陷收益”或“WebGPU 加速”写成既定贡献**；及时启动备用路线。

## 五、A 阶段：最小可运行基础模型与浏览器基线（必须）

### 5.1 模型选型

- 主干：标准 CLIP ViT-B/16，输入 `224×224`，初期**冻结视觉主干**。
- 文本分支：使用少量固定、对象无关的正常/异常 Prompt 集成。初始正常模板为 `an intact industrial object`、`a normal industrial object`、`an industrial object without defects`，异常模板为 `a damaged industrial object`、`a defective industrial object`、`an anomalous industrial object`。分别对各组模板的归一化文本特征求均值并再次归一化，得到固定正常/异常原型；**不训练 Prompt、不使用目标域类别名、不在浏览器部署文本编码器**。
- 视觉分支：先使用单个中间层的 `14×14` Patch 特征及一个线性层/两层 MLP 适配器；单层不足时才扩展到少量固定中间层。
- 预测：Patch 特征与正常/异常原型做归一化相似度，产生粗异常概率或得分图。基础阶段的图像级得分统一取异常图的 `99.5%` 分位值；粗到细阶段按第 6.2.4 节的同一规则计算最终得分，不再并行搜索最大值、全局相似度等聚合方式。
- 损失：固定采用 `Focal Loss + Dice Loss`，即 $L_{\mathrm{seg}}=L_{\mathrm{focal}}+L_{\mathrm{dice}}$；除非基础训练明显不稳定，否则不更换损失函数或搜索额外损失组合。

一个可用的基础匹配形式为：

$$
P_j(\mathrm{abnormal})=\frac{\exp(\operatorname{sim}(z_j,t_a)/\tau)}{\exp(\operatorname{sim}(z_j,t_n)/\tau)+\exp(\operatorname{sim}(z_j,t_a)/\tau)},
$$

其中 $z_j$ 是适配后的 Patch 特征，$t_n,t_a$ 是离线预计算的正常与异常文本原型。**这个公式是基础实现，不单独宣称为创新。**

> 中间层特征并不天然与文本向量良好对齐。适配器是否足以实现有效的语义匹配必须首先通过源域验证；若直接原型匹配效果差，优先检查特征抽取和训练流程，而不是立即加入多个新模块。

### 5.2 实现顺序

1. **PyTorch 端**：先输出正确的 Patch 异常图与图像级分数，打通源域训练/验证和目标域只测试流程。
2. **ONNX**：固定 224 空间尺寸、固定位置编码与输出接口，仅将 Batch 维设为动态，检查模型使用的全部算子；先做单张前向，再分别验证并预热 `B=1/2/4`。若动态 Batch 在目标 WebGPU 环境中不稳定，则用同一模型按 `B=1` 顺序执行；若运行时完全不支持该动态维，则替换为单一的静态 `B=1` 导出版本并记录原因，不同时维护多套重复权重模型。
3. **浏览器端**：上传图像 → 同一预处理 → WebGPU 模型前向 → 异常得分和热力图。
4. **数值一致性**：比较 PyTorch/ONNX/WebGPU 的最终异常分数、Patch 图和样本排序，不只比较某一层最大绝对误差。
5. **性能**：将下载、初始化、首轮执行、稳定推理、预处理与可视化分别计时。

建议 ONNX 输出最初限制为：

```text
input:
  image         [B, 3, 224, 224]
output:
  anomaly_map   [B, 14, 14]
  image_score   [B]
```

后续只有确有需要才增加中间特征输出，避免浏览器端搬运不使用的张量。

#### WebGPU Batch 与 Graph Capture 的分级实施（v3 补充）

- **第 0 级（必要）**：关闭 Graph Capture，确保固定 `224×224`、`B=1` 的模型运行正确，并记录 PyTorch → ONNX CPU → WebGPU 的输出一致性及端到端延迟。
- **第 1 级（必要验证，但允许失败回退）**：保持同一组权重，尝试动态 Batch 下的 `B=1/2/4`，比较顺序执行与 Batch 执行的 P50/P95、显存/内存及失败原因；若不支持则使用稳定的 `B=1` 顺序推理，**不影响 A 阶段验收**。
- **第 2 级（选做）**：只有稳定推理已经完成且 CPU 提交/调度开销确属瓶颈时，才测试 `enableGraphCapture`；需检查静态形状、所有计算内核是否由 WebGPU 执行，以及是否能够通过固定自由维覆盖来满足条件。不得假定动态 Batch 的同一会话会自动对所有 B 都成功捕获或获得加速。
- 每种实现都使用**相同的网络权重、预处理和评分规则**，并区分基线与可选运行时优化的结果。Graph Capture 不属于本课题必须完成的研究贡献。

技术依据：[ONNX Runtime WebGPU 官方说明][ref-ort-webgpu]、[会话与 Graph Capture 选项][ref-ort-options]。

### 5.3 A 阶段验收标准

- 至少一台目标浏览器设备能够本地输出异常分数和热力图。
- 有稳定的数据读取、源域训练、验证、目标域评估及日志脚本。
- 推理链路与数值差异可复现；异常检测结果不是随机输出或未校准的展示效果。
- 完成 224 全图与固定 K ROI 的初步时间测试。

**说明：A 是完整工程与论文实验基础，不把它单独视为必然足以毕业的算法创新。**

## 六、A+ 阶段：两项核心研究内容

### 6.1 M1：面向微小缺陷的缺陷保持与尺度一致性粗检测

**研究动机**：全图缩放以及 Patch 标签下采样可能弱化微小缺陷；只用全图训练的异常头对局部裁剪的尺度分布也可能不适应。

#### M1-1：缺陷保持的 Patch 监督（必做）

在学生 `14×14` 网格上对比：

- 常规双线性/面积下采样掩膜；
- Max-Pooling 保留任一异常像素；
- 仅在必要时探索平滑最大聚合。

固定学生参数、训练样本、损失与训练时长，单独测量缺陷保留方式对 Tiny/Small 召回、Region Recall@K 和 Pixel AP 的影响。

**注意**：Max-Pooling 是成熟技术，本课题的贡献不能仅仅是“把插值换成最大池化”，而应来自对**微小缺陷候选保持问题、训练分布适配与下游局部计算预算**的整体机制设计和实证分析。

#### M1-2：全图/ROI 共享模型训练（必做）

从源域图像生成：

1. 低分辨率全图样本；
2. 覆盖真实异常的正 ROI；
3. 邻近异常但不覆盖缺陷的难负 ROI；
4. 正常区域随机 ROI。

共享同一个视觉主干与异常头，不另训局部模型。各类型的采样比例、裁剪尺度在**源域验证集**选定后冻结。

建议最小训练目标为：

$$
L_{M1}=L_{\mathrm{seg}}(A_{\mathrm{full}},Y_{\mathrm{full}})
+\lambda_{\mathrm{roi}}L_{\mathrm{seg}}(A_{\mathrm{roi}},Y_{\mathrm{roi}}).
$$

无需初始就加入复杂知识蒸馏、上下文门控或不确定性网络。

#### M1-3：区域排序约束（可选增强）

只有出现“粗图可以检测，但候选 Top-K 排序经常漏掉小缺陷”，且 M1-1/M1-2 收益不足时，再添加简单 Margin Ranking：

$$
L_{\mathrm{rank}}=\max(0,m-s_{+}+s_{-}).
$$

不能因为公式简单就默认有效；必须新增“有/无排序损失”消融。若收益不稳定，删除模块。

#### M1 验证任务

- 粗图 Pixel AP、Tiny/Small 检出与 Region Recall@K；
- 全图训练 vs 全图+ROI 联合训练；
- 常规标签下采样 vs 缺陷保持；
- 单层 vs 少量多层 Patch 特征（仅当单层明显不足）；
- 保持候选窗口面积和 K 不变，排除“通过扩大覆盖区域提高召回”的混淆。

**M1 通过条件**：至少有一个机制在源域验证与冻结后的目标域实验中展示一致方向的非偶然收益，并能解释对最终 ROI 候选覆盖的影响。不得只凭源域训练集改善认定有效。

### 6.2 M2：WebGPU 实测成本驱动的自适应局部细化

**研究动机**：固定每张图像都处理相同数量 ROI，可能浪费正常或简单图像的计算，也不适应不同 WebGPU 设备的时延表现。

#### M2-1：简单候选基线（必做）

先实现固定尺度的滑动窗口/网格候选，然后依次比较：

- 随机 ROI；
- 固定均匀网格 ROI；
- 粗图异常分数 Top-K；
- Top-K + NMS 去重。

基础窗口风险可以是窗口内最高/高分位异常分数与均值的固定加权，**所有参数仅使用源域验证**确定。

#### M2-2：异常响应加权的覆盖收益（必做）

为防止算法偏好覆盖大量正常背景，定义候选集合对**粗图异常响应**的新增覆盖，而不是仅最大化几何面积：

$$
F(S)=\sum_{p\in \cup_{i\in S}\Omega_i} w(p),\quad
w(p)=\operatorname{clip}(A_{\mathrm{coarse}}(p),0,1).
$$

可将高分位响应作为微小缺陷保护项；覆盖收益对已经覆盖的区域不重复计算，天然减少重叠。窗口尺寸、长宽比与候选密度先固定，保证与 Top-K/NMS 公平比较。

该公式仍属于简单的集合覆盖思路，其价值需要体现为**任务适配、算法低成本和与设备预算的联合实验**，不宣称通用最优解。

#### M2-3：设备成本与动态 K（必做）

在每种设备 $d$ 上使用固定形状/合成图像测量：

$$
\widehat C(K,d)=T_{\mathrm{full}}(d)+T_{\mathrm{select}}(d)
+T_{\mathrm{crop+upload}}(K,d)+T_{\mathrm{roi}}(K,d)+T_{\mathrm{fuse}}(K,d).
$$

固定候选集合为 $K\in\{0,1,2,4\}$；实测不同 Batch 形状的加载、预热、P50/P95、内存和失败情况。**不能用 FLOPs 代替 WebGPU 真实延迟**。

在设备预算 $B_d$ 内，优先选择新增异常覆盖收益高的候选，并在新增收益/新增代价低于源域确定的阈值时停止：

$$
\frac{\Delta F}{\max(\Delta\widehat C,\varepsilon)}<\eta
\quad\Longrightarrow\quad \text{停止增加 ROI}.
$$

实施时不必精确求解复杂组合优化；**贪心选择 + 离散成本表**即可先形成论文方法。

需要注意：设备感知并不自动等于新的算法贡献。如果不同设备的策略只是简单改变最大 K，必须用固定 K、相同预算、简单阈值与无设备感知动态 K 的对比证明所建模的边际成本确有意义。

#### M2-4：局部热力图回投和融合（必做）

- 从**原图**裁剪被选中的 ROI，再缩放为 224；不能直接裁剪已经缩到 224 的全图。
- 单次局部模型与全图共享权重；使用同一个动态 Batch ONNX 模型执行 `B=1/2/4`，并对这些形状分别预热。动态 Batch 不稳定时按 `B=1` 顺序执行并报告额外代价。
- 先将粗异常图上采样到原图尺寸，并将各 ROI 异常图回投至对应原图区域。最终热力图采用逐像素最大融合：

$$
A_{\mathrm{final}}(p)=\max\left(A_{\mathrm{coarse}}^{\uparrow}(p),\max_{i:p\in\Omega_i}A_{\mathrm{roi},i}^{\rightarrow}(p)\right).
$$

- 图像级异常分数固定为最终热力图的 `99.5%` 分位值，即 $s_{\mathrm{image}}=Q_{0.995}(A_{\mathrm{final}})$；K=0 时该定义自然退化为粗异常图的同一聚合规则。异常判定阈值只在源域验证集确定并冻结。
- 不训练复杂融合网络，不使用目标域选择融合方式、分位值或异常阈值。
- 统一记录坐标变换、缩放、padding 与插值规则；不同对照必须采用同一预处理。

#### M2-5：不同 K 下的异常分数漂移与误报检查（v3 补充，必要评价而非新模型）

最大值融合加上最终热力图 `99.5%` 分位数评分，可能使局部预测次数增加时正常图像的异常分数系统性上升。为了确保动态 K 的收益不是评分偏移造成的，补充一项**低开销诊断实验**：

1. 在**相同的源域验证图像**上，强制运行 `K=0/1/2/4`（不改变模型权重），分别统计正常图像的 `s_image` 分布、中位数/P95、源域固定阈值下的假阳性率，以及异常图像的检出变化；记录分数与 K 的相关关系。
2. 在冻结配置后的两个目标域测试上，按照同一统计脚本仅作**事后分析**，报告不同 K 的正常/异常评分分布、正常图像误触发 ROI 的比例，以及异常图像被 `K=0` 提前跳过的比例。**不得据此重新选择分位值、阈值或融合参数。**
3. 若分数漂移明显，先检查全图与 ROI 输出量纲、归一化和热力图回投，保持现有最大融合为首选基线；确有必要时，只允许根据**源域验证集**拟合一个简单、固定的全图/ROI 分数校准规则，并与“未校准”版本独立消融。**不默认开发新融合网络。**
4. 图像 AUROC/AP 与固定源域阈值下的 FPR/TPR 均需报告；前者评价排序，后者体现实际判别阈值的影响，不能仅用 AUROC 掩盖误报增加。

**通过要求**：若动态 K 的检测结果提升同时导致显著误报升高，必须如实呈现精度与误报权衡，不能仅凭最终 Pixel 指标上升宣称整体方法更优。

#### M2 验证任务

- 对照：固定高分辨率全图（可运行时）、固定 K、随机 ROI、固定网格、Top-K+NMS、简单阈值动态 K、动态 K 不看设备成本、完整方法；
- 必须报告固定预算下精度和固定精度下延迟，并给出真实端到端 Accuracy–Latency 曲线；
- 统计正常/异常图像各自的平均 K、平均耗时、P50/P95，避免只报告整体平均掩盖漏检；
- 将 ROI 调度本身的计算成本计入总延迟；
- Oracle ROI 仅作为分析性上界，**绝不参与正式零样本方法评分**。

**M2 通过条件**：在至少一个事先定义的实验设置中，相对有竞争力的固定 K 或简单动态阈值对照出现可重复的精度—延迟改善；若不成立，按照止损规则保留负面结果，不宣称加速。

## 八、实验设定、数据隔离与评价指标

### 8.1 跨数据集零样本协议

| 方向 | 源域训练及源域验证 | 目标域最终测试 |
|---|---|---|
| A | MVTec AD | VisA |
| B | VisA | MVTec AD |

- 源域允许使用异常图像和掩膜；训练、验证数据必须不重叠，划分清单与随机种子留档。
- 尽可能采取源域**按类别划分训练/验证**；若类别过少影响稳定性，可以使用提前定义的分层图像划分，但必须说明该改变及可能的泛化影响。
- 目标域数据在冻结模型、融合、阈值、ROI 大小、停止规则等配置前不可用于方法选择；正式测试结果不得反向指导修改。
- 开发初期可先在 **MVTec AD 源域选 3～6 类**进行数据与代码排错；为防止隐性泄漏，VisA 只在冻结阶段作为目标域测试。
- 两个迁移方向分别构成独立实验：每个方向只允许使用其源域完成训练、验证和参数冻结，并分别记录权重、配置及源域划分。某数据集在一个方向中作为目标域得到的测试结果，不得反向参与该方向的方法选择；当它在反向实验中转为源域时，须重新训练独立模型，不能与前一方向共享调参过程。
- 固定 Prompt 集成只使用预先确定的对象无关模板，不引入目标域类别名，避免因人工指定测试类别提示造成不可比较。

**两个迁移方向的“冻结—评测”操作协议（v3 补充）：**

1. **共同方法冻结**：在正式读取任何目标域测试结果前，冻结 M1/M2 的算法结构、对照组、指标定义、ROI 候选尺度集合、`K={0,1,2,4}`、融合公式、图像分数聚合形式、统计脚本和源域参数选择规则，并记录代码提交版本。
2. **每方向独立源域验证**：方向 A 只在 MVTec AD 的源域训练/验证数据上训练与选择允许的参数；方向 B 只在 VisA 的源域训练/验证数据上独立重训与选择参数。允许源域选择的范围（如停止阈值、权重、学习率）应事先列明；不能依据目标域结果扩充搜索空间。
3. **模型冻结记录**：分别保存模型权重哈希、Prompt 列表、训练/验证类别与图像清单、随机种子、选择指标、阈值、ROI 尺度、融合与停止配置。必要的设备成本微基准只能使用合成输入或固定形状数据。
4. **目标域最终测试**：分别对 VisA 和 MVTec AD 执行一次正式结果生成流程；若发现代码错误，记录错误、修复提交与全部重跑范围，不选择性保留有利结果。目标域标签仅用于最终评分和预先约定的事后缺陷尺寸分层。
5. **跨方向信息隔离**：某数据集在 A 中作为目标测试集、在 B 中作为源域数据并不自动使两组实验无效，但**不允许 A 的目标测试反馈改变 B 或 A 使用的共同算法设计**。若确需事后探索，应明确标为探索性分析，不纳入预注册式主结论。

这个协议不要求两个方向同时训练；只是要求在正式目标测试前锁定共同规则。实施时优先跑通单向的**源域开发流程**，待整体方案冻结后再开展两方向正式测试。

### 8.2 检测指标

- **主指标**：Image AUROC、Image AP、Pixel AUROC、Pixel AP、AUPRO（写清具体计算协议）。
- **小缺陷专项**：Tiny/Small 分组上的缺陷召回、Pixel AP/AUPRO；粗阶段 Region Recall@K 和真实缺陷像素覆盖率。
- **定义统一**：以异常掩膜占整图面积比例划分 Tiny/Small/Other，分位点只用于**测试后分层分析**，不得参与训练及模型选择；明确是全数据集分位还是按类别分位。
- **ROI 公平性**：限制并报告窗口尺寸、覆盖面积比例、窗口重叠率；不能通过扩大 ROI 人为抬高 Recall@K。
- **误报/漏检**：尤其记录 K=0 时异常样本被跳过的比例，以及正常图像误触发细化的比例；增加**正常样本在固定 K=0/1/2/4 下的分数漂移与固定源域阈值的假阳性率**。

### 8.3 计算与系统指标

- 模型文件大小、模型加载和首次推理时间；
- 预热后端到端 P50/P95、均值和吞吐；
- 全图、候选排序、裁剪/上传、ROI Batch、融合各阶段耗时；
- CPU 内存/可测 GPU 内存、支持与失败情况；
- 正常/异常样本分别统计延迟和平均 K；
- PyTorch、ONNX CPU 与 WebGPU 异常图/图像分数/样本排序的一致性。

### 8.4 必要对照和消融（避免爆炸式组合）

| 分组 | 最少对照 | 目标 |
|---|---|---|
| 基础能力 | 固定对象无关 Prompt 集成的单层 Patch 头；纯 CLIP 弱基线 | 证明基础异常模型真实有效 |
| 局部观察价值 | 224 全图；Oracle 1/2 ROI；可运行时 448 全图 | 证明局部细化上界 |
| 候选有效性 | 随机、固定网格、Top-K、Top-K+NMS | 证明粗图有实际选择价值 |
| M1 | 普通下采样 vs 缺陷保持；仅全图 vs 全图/ROI 联合训练 | 证明缺陷保持与尺度适配收益 |
| M2 | 固定 K=0/1/2/4；简单阈值动态 K；设备感知动态 K | 证明动态预算并非简单减少 ROI |
| 系统 | 224；224+K；448 可运行时 | 比较实测性能及失败边界 |
| 分数与误报安全性 | 同一批正常图像固定 K=0/1/2/4；冻结阈值下 FPR | 排除 ROI 数量增加造成的异常分数虚高 |

**研究增强时再增加的消融**：Margin Ranking、有无多层 Patch、风险覆盖贪心与 NMS、教师蒸馏、可学习 Prompt。不要在研究开始时展开所有组合。

### 8.5 结果呈现原则

应至少输出下列图表：

1. Tiny/Small 缺陷规模与 224 全图性能关系；
2. Oracle 与真实 Top-K 的 Region Recall@K；
3. M1 消融表与局部热力图可视化；
4. 不同 K 的端到端 P50/P95 与内存；
5. 完整 Accuracy–Latency Pareto 曲线；
6. 两个迁移方向与两类硬件结果、失败案例。

统计中区分**源域验证**与**冻结后的目标域测试**；如果某项贡献在目标域不稳定，应明确报告而非选择性展示有效类别。

## 九、前两周 Go / No-Go 可行性验证（最关键）

### 9.1 四个最小证明

| 检查项 | 要做的最小实验 | 必须回答的问题 |
|---|---|---|
| P1 基础异常检测 | 在源域选 3～6 类实现并验证固定对象无关 Prompt 集成 + Patch 头 | 模型是否有可靠异常信号？ |
| P2 WebGPU 基础兼容 | 固定 224 ONNX 模型在至少一台 WebGPU 设备运行 | 模型能否真正跑起来？ |
| P3 Oracle ROI 有效性 | 224 全图 vs 全图+Oracle 1/2 ROI，真实掩膜只用于上界 | 小缺陷局部观察是否有可利用的提升？ |
| P4 ROI 成本 | 测 224、224+1/2/4 ROI，以及可运行时的 448 | 少量 ROI 是否有可接受的真实耗时？ |

### 9.2 推荐日程与具体产物

**第 1 周**

- D1–D2：检查数据目录、掩膜配对、源域开发子集、预处理与固定随机种子；
- D3–D4：跑通 CLIP 特征与最简 Patch 头；生成异常分数和热力图；
- D5–D7：导出静态 224 ONNX，并在 WebGPU 端进行第一轮正确性和时延测试。

**第 2 周**

- D8–D9：实现 Oracle/随机/固定网格/Top-K ROI 的坐标裁剪、回投；
- D10–D11：测试固定 K ROI 顺序/Batch 和 448 可行性，分阶段记时；
- D12–D14：整理 Tiny/Small 分组、Oracle 上界、真实候选召回、延迟曲线和书面 Go/No-Go 结论。

以上日程是**优先级顺序**而非保证每天都能完成的承诺。若 P1/P2 未通过，不应为了完成日期而跳过必要验证。

**两周验收的最低可交付与缓冲规则（v3 补充）：**

- 两周内应优先获得 **P1 的有效异常响应（可以是少量源域验证样本）+ P2 的 WebGPU `B=1` 前向正确性**；P3 的 Oracle 上界与 P4 的基础延迟对照尽量同步完成。
- 若完整源域训练、动态 Batch 或 448 高分辨率导出超时，可以延续至第 3–4 周；第 2 周结论标记为**“证据未齐，暂缓 Go/No-Go”**，而不是错误判断研究假设失败。
- **未经 P3/P4 核心证据，不进入需要数周训练的复杂 M1/M2**；若第 4 周仍未建立可运行基线，应启动原有模型与浏览器兼容性的降级处理，避免六个月排期失控。
- Graph Capture、可学习 Prompt、教师蒸馏、区域排序学习等都不能替代上述最小证明。

### 9.3 决策准则

| 结果 | 决策 |
|---|---|
| P1 不成立：异常分数接近随机 | 先修复特征抽取、掩膜对齐、训练与数据，必要时换成熟的轻量异常头；暂停 M2 |
| P2 不成立：224 无法 WebGPU 执行 | 定位算子/显存/浏览器差异；先在独显验证，实证后才考虑 ViT-B/32 |
| P3 不成立：Oracle ROI 仍无收益 | 停止复杂粗到细调度，转向缺陷保持轻量模型研究 |
| P3 成立但 Top-K 召回低 | 先推进 M1，重点验证缺陷保持与 ROI 联合训练 |
| P3 成立但 P4 成本极高 | 限制 K、优化 Batch/上传；仍无潜力则转向备用路线 |
| P1–P4 基本支持 | 正式进入 M1 → 固定 K → M2 动态 K 的顺序 |

不预设死板的“必须加速 30%”等门槛；但任何正向结论必须具有可重复的对照证据。

## 十一、风险矩阵与备用论文路径

| 风险 | 表现 | 优先处置 | 最终退路 |
|---|---|---|---|
| ViT-B/16 兼容性不足 | ONNX 不支持/运行异常或显存不足 | 固定位置编码、检查算子、减 Batch、独显验证 | 经记录后用 ViT-B/32 或已验证的轻量骨干 |
| 基础异常头精度差 | 粗图无稳定异常响应 | 检查中间层表征、适配器、标签、训练过程 | 采用经过验证的异常检测型轻量头 |
| ROI 精度上界不成立 | Oracle 不优于全图 | 分析裁剪尺度和缺陷视觉信息 | 终止粗到细，专注轻量缺陷保持模型 |
| 候选漏检多 | Top-K 找不到缺陷 | M1、合理候选尺度、ROI 联合训练 | 固定网格作为分析对照；不强行叠加学习式选择器 |
| WebGPU 无实际效率优势 | 224+ROI 速度慢或 P95 不稳 | 测 Batch、上传和 K 的成本；限制为 0/1/2 | 不再以“加速”为贡献，转轻量检测/资源权衡 |
| 跨域结果不稳 | 一个迁移方向提升、另一方向下降 | 记录差异，分析类别与缺陷尺度，不在目标域调参 | 缩小结果表述或与导师调整论文定位 |
| 时间不足 | 四个月仍缺主要对照 | 停止 B，优先实验和论文 | 不增加大模块 |

### 11.1 备用研究方向（必须提前保留实验骨架）

**暂定题目：基于 WebGPU 的缺陷保持型轻量视觉语言异常检测方法。**

当粗到细收益不成立时，仍沿用已训练的 CLIP 轻量异常头、WebGPU 系统、掩膜聚合和 ROI 联合训练代码，转为研究：

1. **缺陷保持 Patch 监督机制**：下采样策略、类别/面积不均衡、损失权重与微小缺陷保留；
2. **全局—局部尺度一致性异常表示**：全图/ROI 共享训练、轻量特征对齐、对正常纹理误报与微小缺陷的影响；
3. **浏览器部署与精度—资源权衡**：固定分辨率及模型复杂度对精度、延迟和内存的影响。

但必须清楚：**单独使用 Max-Pooling、联合训练或网页系统，不自动构成足够的学术创新**。备用路径若要作为最终学位论文，需要在正式相关工作比较和独立消融后提炼新的方法贡献，并提前同导师确认其满足学院要求。

### 11.2 B 阶段可选项（最多一个）

只有当双向实验、M1/M2 消融和浏览器结果已经完成后，才可按实际瓶颈选择：

- 固定 Prompt 确实限制精度 → 可学习 Prompt；
- 粗图候选仍漏检 → 简单区域排序损失或一次前向不确定性（择一）；
- 粗阶段缺陷弱且教师可用 → 离线 AnomalyCLIP 软标签蒸馏；
- 实测明确是加载/内存瓶颈 → FP16 或模型/权重缓存优化。

不把 B 项作为毕业的依赖条件。

## 十二、拟形成的研究贡献（待验证，不写成既定事实）

### 贡献一：面向微小缺陷的低成本候选保持学习

分析低分辨率 Patch 监督中的微小异常信息弱化问题，并将**缺陷保持监督与全图/ROI 一致训练**用于改善有限局部预算下的候选召回。需通过独立消融与跨数据集结果证明效果，不能把成熟算子的简单组合直接作为“首次提出”。

### 贡献二：面向 WebGPU 的实测延迟约束自适应局部细化

将区域异常响应加权覆盖、少量 ROI 的局部观察和**设备实测成本**结合，使不同图像和设备按预算确定局部计算量。重点通过固定 K、简单阈值动态 K、无设备成本版本和真实 Pareto 对比证明价值。

### 贡献三：浏览器端工业多模态异常检测闭环与可复现评估

设计并实现浏览器端工业多模态异常检测闭环，包括本地 WebGPU 推理、动态候选调度、局部 Batch、热力图回投和跨硬件性能分解；通过端到端实验明确 WebGPU 的兼容边界、实际开销和失败模式。该项作为论文第三项研究贡献，以系统架构、可复现实测与完整闭环支撑，而非仅凭网页展示。

> **创新性风险声明**：粗到细、多尺度、Patch 监督、覆盖贪心与预算调度等基础思想已有相关研究。本文的学术主张必须限定到具体的微小缺陷任务、源域监督/目标域零训练设定、轻量模型与 WebGPU 实测约束的联合设计，并以相关工作差异分析和实验结果为依据。

## 十三、建议论文结构

1. **绪论**：工业异常检测需求、视觉语言异常检测、浏览器端推理背景、研究问题与贡献。
2. **相关工作与技术基础**：CLIP 与零样本工业异常检测、微小缺陷与多尺度方法、动态计算分配、ONNX Runtime WebGPU。
3. **轻量视觉语言异常检测与 WebGPU 系统设计**：基础模型、固定对象无关 Prompt 集成/异常头、模型转换、浏览器分工、初步基线。
4. **缺陷保持与预算约束的粗到细异常检测方法**：M1、M2、候选选择、局部融合与复杂度分析。
5. **实验与讨论**：跨数据集结果、M1/M2 消融、小缺陷分析、分阶段延迟、Pareto 曲线、失败案例。
6. **总结与展望**：成立条件、部署约束、方法局限及可选改进。

如果最终进入备用研究方向，第 4 章重心调整为“缺陷保持与尺度一致性异常学习”，第 5 章不再构造不存在的动态加速收益。

## 十五、最终执行原则

> **先实现一条稳定、可复现的“CLIP 异常检测 → ONNX WebGPU → 浏览器热力图”链路；用 Oracle 和真实 ROI 验证粗到细是否值得做；再以“缺陷保持与全图/ROI 一致训练（M1）+ 设备实测成本的动态 ROI（M2）”形成核心研究。**

如果局部细化不具备实际优势，就及时切换已准备好的轻量缺陷保持路线，不继续堆叠不确定性网络、复杂蒸馏或内核优化来掩盖负面结果。

**毕业优先的含义是控制研究依赖、提前形成实验闭环，而不是降低学术标准。** 毕业结论取决于方法独立贡献、可信对照和学院导师的最终认定；本文件不承诺未经验证的加速或精度收益。
