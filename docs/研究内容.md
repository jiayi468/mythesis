# 基于 WebGPU 的工业多模态异常检测方法——毕业优先研究方案（修订版）

> 修订日期：2026-10-16  
> 版本定位：六个月实施；优先实现、保证研究深度、严格控制核心工作量。  
> 来源说明：基于《2026-10-16-webgpu-industrial-anomaly-detection-design.md》调整。固定“缺陷保持粗检测、预算约束局部细化、浏览器端系统”三项贡献；保留跨数据集零样本设定、CLIP ViT-B/16 学生和实测延迟评价；降低教师蒸馏、不确定性学习、复杂融合的优先级。

## 一、研究定位与题目

**论文题目：基于 WebGPU 的工业多模态异常检测方法**

研究目标不是“把 AnomalyCLIP 搬到浏览器”，也不是“做一个网页检测 Demo”，而是：

> 在不使用目标域样本进行训练、调参或阈值选择的跨数据集零样本设定下，研究一种低开销的视觉语言异常检测与局部细化策略，在浏览器 WebGPU 设备上取得可验证的检测精度—推理延迟权衡优势。

**论文主线收敛为一项：面向微小缺陷的低成本粗到细自适应推理。** 研究形成两项相互衔接的算法创新和一项系统创新：第一项解决低分辨率粗检测容易遗漏微小异常的问题，第二项解决有限 WebGPU 延迟预算下局部计算如何分配的问题，第三项完成浏览器端闭环实现与分阶段实测评价。复杂教师蒸馏和学习式不确定性网络不属于必须完成的内容。

研究价值在于：工业异常通常局部、稀疏，均匀高分辨率推理可能在大量正常区域上浪费计算；浏览器 WebGPU 对延迟和内存敏感，因此适合研究**以任务风险指导计算分配**的方法。该价值属于研究假设，必须用实测验证，不能事先声称一定更快。

## 二、固定研究边界

- **论文类型**：学术硕士；实际是否满足毕业标准，以导师和学院要求为准。
- **周期**：六个月；当前尚无可复现模型基线。
- **训练硬件**：优先单卡 24 GB NVIDIA GPU；16 GB 作为降级方案。
- **浏览器测试设备**：AMD 集显笔记本（联想小新 Air-14ARE 2020）+ 至少一台 NVIDIA 独显设备。
- **数据集**：MVTec AD 与 VisA；第一阶段仅抽取 3～6 类作方法开发与验证，正式实验再覆盖全部类别。
- **核心模型**：CLIP ViT-B/16 视觉编码器（固定 224×224）+ 多层 Patch 特征适配器 + 正常/异常文本原型匹配头。只有在预先记录的 Go/No-Go 验证证明 ViT-B/16 无法在目标 WebGPU 设备稳定执行时，才降级为 ViT-B/32；主实验不得混用骨干得出因果结论。
- **运行时**：ONNX Runtime Web + WebGPU；TypeScript 实现 ROI 调度、NMS、预算选择、坐标映射；非必要不写自定义 WGSL。
- **浏览器端**：不进行训练，不加载文本编码器；正常/异常文本原型离线计算并打包。
- **严格限制**：不同时开展混合量化、通用 Token Pruning、自定义 Attention Shader、复杂蒸馏、多模型联合部署。

## 三、研究问题和可检验假设

**RQ1：** 使用轻量视觉语言编码器，能否在浏览器 WebGPU 中得到稳定、可复现的工业异常分数与像素级热力图？

**RQ2：** 相比全图 224 输入，通过少量候选区域的局部 224 推理，能否改善微小缺陷检出与定位？

**RQ3：** 相比固定 K 个 ROI 或固定高分辨率全图推理，联合考虑候选异常风险、空间覆盖收益和设备实测成本，能否在相似精度下减少实际 WebGPU 延迟？

对应的最低可证伪假设：

1. **局部有效性**：Oracle ROI 至少在部分小缺陷类别上明显优于全图 224；若不成立，停止粗到细路线。
2. **候选有效性**：简单异常分数 Top-K + 去重，比随机候选更有用；若收益小，使用固定网格作为对照或退出候选学习方向。
3. **设备有效性**：至少在一个明确的精度区间内，预算约束的少量 ROI 能形成实测精度—延迟 Pareto 优势；若不成立，不强行宣称部署加速。

研究假设失败也必须完整报告；**失败不等于可以把不成立的加速效果写成论文贡献**。

## 四、简化后的总体方案

```text
                离线准备（PyTorch）
    源域数据集 ──> CLIP 视觉编码器 + 轻量异常头
                 正常/异常文本原型预计算
                             │
                       ONNX 静态导出
                             │
                浏览器 WebGPU（仅推理）
                             │
              原始工业图像（保持原尺寸）
                             │
                        全图缩放 224
                             │
                       全图粗异常图
                             │
              风险候选生成 + 覆盖去重
                             │
          ┌──────────────────┴─────────────────┐
          │ 边际收益低：结束  │ 预算内选 1~4 ROI │
          └──────────────────┬─────────────────┘
                             │
                  原图裁剪 ROI → 224
                             │
                 同一轻量模型局部推理
                             │
                  局部热力图回投 / 融合
                             │
               图像级异常分数 + 异常图
```

### 4.1 基础模型（必须）

- 采用固定 224×224 输入的 CLIP ViT-B/16 图像编码器，提取全局特征以及若干固定中间层的 Patch 特征。
- 使用共享的轻量视觉适配器将不同层 Patch 特征投影到文本语义空间。适配器采用线性层或两层 MLP，不修改 Transformer 内部 Attention，保证 ONNX 导出可控。
- 正常/异常文本原型采用对象无关的可学习 Prompt：以固定的正常/异常语义模板初始化上下文参数，只在源域训练上下文参数；训练完成后离线编码并固化为模型常量，浏览器不加载文本编码器。固定手工 Prompt 仅作为对照。
- 每层 Patch 特征与正常/异常文本原型计算归一化相似度，经固定或可学习的层权重融合为 Patch 异常图；全局特征以相同原型产生图像级异常分数。
- 基础训练阶段冻结 CLIP 主干，仅训练视觉适配器、层融合权重和温度参数；只有源域验证证明不足时，才解冻最后 2～4 个 Transformer Block。
- 纯 CLIP Patch—文本直接匹配仅作为弱基线，不作为最终基础模型。正式方法至少包含上述轻量异常适配器。
- 先在 PyTorch 端验证正确性，再导出 ONNX；模型数值差异和 WebGPU 算子支持逐项核对。
- 初版不引入 `global_context`、随机不确定性推理或教师网络。

### 4.2 核心算法：缺陷保持 + 预算约束自适应 ROI（A+ 必做）

**模块 M1：缺陷保持与选择导向的粗异常学习（算法创新一）**

- 将源域真实异常掩膜从高分辨率映射到学生 14×14 Patch 网格，对比双线性/面积下采样、Max-Pooling 和平滑 Max-Aggregation。缺陷保持聚合负责避免小异常在标签映射中消失。
- 源域训练同时构造四类输入：低分辨率全图、覆盖异常的正 ROI、邻近异常但不覆盖的难负 ROI、随机正常 ROI。全图和 ROI 共享视觉编码器与异常头，使模型在浏览器局部裁剪推理前已经见过相应尺度分布。
- 使用 Focal/BCE 与 Dice 训练 Patch 异常图；具体采用 Focal 还是 BCE 由源域验证确定，但所有对照使用相同选择。
- 增加轻量区域排序约束，使覆盖异常的候选得分至少比难负候选高出间隔 `m`：

\[
L_{rank}=\max(0,m-s_{pos}+s_{neg}).
\]

- 总损失保持简单：

\[
L_{M1}=L_{seg}+\lambda_{rank}L_{rank}.
\]

- M1 的目标是提升 Tiny/Small 缺陷的粗检测召回和有限预算下的 Region Recall@K，不要求粗阶段直接达到最终像素分割精度。
- 必须消融：普通标签下采样、缺陷保持聚合、是否加入 ROI 视图训练、是否加入区域排序。

**模块 M2：风险覆盖与 WebGPU 延迟预算约束的局部细化（算法创新二）**

- 根据粗异常图生成候选窗口。每个窗口的基础风险 `s_i` 由窗口内的最大/高分位异常响应和平均异常响应组合得到；组合权重只在源域验证集确定。
- 候选集合 `S` 通过贪心方式优化风险覆盖收益，并惩罚区域重叠：

\[
\max_S \sum_{i\in S}s_i+\alpha Coverage(S)-\beta Overlap(S),
\quad C(|S|,d)\le B_d.
\]

其中 `C(K,d)` 是设备 `d` 上实测的全图、ROI Batch、裁剪上传和融合总成本，`B_d` 是设备延迟预算。
- 候选数量限定为 `K ∈ {0,1,2,4}`。当下一候选的新增风险覆盖与新增实测延迟之比低于源域确定的阈值时停止：

\[
\frac{\Delta Risk}{\Delta Latency}<\epsilon.
\]

- 从原图裁剪已选 ROI 并缩放到 224，复用同一模型组成 Batch 推理，不新增第二个视觉编码器。
- ROI 热力图回投后，使用固定的最大残差或置信度加权规则与粗图融合；融合规则通过源域验证选择，不训练额外融合网络。
- 必须比较：随机 ROI、固定网格、Top-K + NMS、固定 K 风险覆盖、无延迟预算的动态 K、完整预算约束方法以及 Oracle ROI。

**联合逻辑**：M1 负责“不要在粗阶段漏掉值得看的区域”，M2 负责“在当前设备预算内决定看哪里、看多少”。两者构成同一粗到细算法链，但分别具有独立问题、机制、指标和消融。

### 4.3 浏览器端系统与分阶段实测（系统创新三，必须）

- 构建纯浏览器端工业多模态异常检测系统，实现模型加载、图像预处理、全图推理、候选生成、ROI Batch、热力图回投、结果展示和失败回退。
- 视觉编码器和异常头由 ONNX Runtime WebGPU 执行；TypeScript 负责候选生成、贪心预算选择、NMS、坐标映射和控制流。动态控制不强行导入 ONNX。
- 建立统一的分阶段计时与复现实验协议，分别记录模型下载/初始化、首次 Shader 编译、全图前向、候选选择、ROI 裁剪与上传、局部 Batch、融合和端到端延迟。
- 至少覆盖 AMD 集成显卡和 NVIDIA 独立显卡两类设备，报告支持失败、内存不足和高分辨率基线无法运行等负面结果。
- 系统贡献必须体现为可复现架构、明确执行边界和完整实测，而不是仅展示网页界面。

### 4.4 可选增强（B，不影响主论文完成）

只在主实验已经站住脚、距离提交尚有余量时，从下列项中**最多选择一项**：

1. **教师软异常图蒸馏**：离线 AnomalyCLIP 高分辨率响应指导粗异常头；若收益小即取消。
2. **一次前向的不确定性排序**：多层/多 Prompt 分歧用于改善 Region Recall@K；不默认训练复杂的区域风险评分器。
3. **上下文融合或 FP16/缓存优化**：以消融或 WebGPU 性能瓶颈为依据，不单独包装成算法创新。

## 五、实验设定与防止结论失真

### 5.1 零样本定义

采用原方案的**跨数据集零样本**设定：源域允许使用图像、标签和异常掩膜训练；目标域图像/标签/阈值均不得参与训练或超参数选择。

- 主实验 A：使用 MVTec AD 的异常图像、正常图像和掩膜构造源域训练/验证集，训练一个模型；VisA 仅作完整目标域测试。
- 主实验 B：使用 VisA 的异常图像、正常图像和掩膜构造源域训练/验证集，重新训练另一个模型；MVTec AD 仅作完整目标域测试。
- 源域优先按产品类别划分训练与验证类别；若类别数量导致验证波动过大，再采用按类别分层的图像划分，并在论文中报告划分清单和随机种子。
- 源域原测试部分中的异常样本一旦用于辅助训练或验证，不再把同一方向的源域性能作为普通测试结果报告。
- 所有超参数、文本 Prompt、排序间隔、融合规则、停止阈值和设备预算均只在源域验证集确定；目标域结果不能反向选择最终参数。
- 两个迁移方向分别训练、分别冻结配置并分别测试，不使用目标域正常样本校准分数。
- 开发阶段列出的 MVTec 六类别仅用于方向 A 的源域诊断；VisA 目标结果在冻结配置前不得用于方法选择。
- 零样本指**对目标域零训练**，并不意味着模型从未接受源域异常监督；论文中必须写清。

### 5.2 必要对照

| 对照组 | 要证明什么 |
|---|---|
| CLIP 224 全图 | 简单基线 |
| CLIP 448 全图（若可正常导出并运行） | 高分辨率性能与开销参照 |
| 224 + 固定网格 ROI | 排除“只要多裁剪就能改善”的解释 |
| 224 + 随机 ROI | 候选排序是否真的有用 |
| 224 + 固定 K 的 Top-K ROI | 证明动态预算优于固定分配 |
| 224 + 动态 K ROI | 最终方法 |
| 常规掩膜下采样 vs 缺陷保持聚合 | 验证 M1 贡献 |
| 仅全图训练 vs 全图/ROI 联合训练 | 验证尺度分布适配贡献 |
| 无区域排序 vs 区域排序 | 验证选择导向训练贡献 |
| Top-K + NMS vs 风险覆盖贪心 | 验证候选集合优化贡献 |
| 无延迟预算 vs 延迟预算约束 | 验证 WebGPU 成本建模贡献 |
| 无局部细化 vs 局部细化 | 验证 M2 贡献 |
| Oracle ROI（仅分析） | 估计局部检测潜力上界；禁止与真实部署方案混淆 |

若完整 ViT-B/16 448 方案在集显上不可运行，必须明确记录“无法运行”；可增加另一台设备上的 448 对照，不应伪造其延迟，也不要求所有基线必须在所有设备上成功。

### 5.3 检测指标

- Image-level AUROC / AP；Pixel-level AUROC / AP / AUPRO。
- 按异常掩膜面积划分 Tiny/Small/Other（分组规则在分析前固定，明确分母与边界）。
- Region Recall@K、异常像素覆盖率、每张图像平均 ROI 数；记录 ROI 尺寸与覆盖面积，防止扩大窗口导致虚高召回。
- 主要检验 M1/M2 在微小缺陷上的贡献；整体指标不得只报提升类别。

### 5.4 系统指标

- 模型文件体积、下载/初始化时间、首轮推理、预热后 P50/P95。
- 至少分解全图前向、候选生成、ROI 裁剪/上传、局部推理、热力图融合的时间。
- CPU/可测 GPU 内存、崩溃/不支持情况、批处理与顺序运行差异。
- 同一设备、同一浏览器版本、同一预热与测试次数下比较；分别报告正常/异常图像耗时。
- 与 PyTorch/ONNX 参考输出对比，以分数、热力图和最终排序一致性为主；绝对误差阈值应随数值精度和输出尺度定义，不能机械使用一个全局阈值。

### 5.5 成功标准（分层，不用未经验证的数字锁死课题）

**毕业论文研究目标**：形成一个可复现的视觉语言异常检测方法和浏览器系统；M1 与 M2 均给出独立消融，其中至少一项在两个迁移方向上取得可信提升，另一项至少在一个迁移方向上取得与其设计目标一致的正向结果；完成两类 WebGPU 设备上的分阶段实测和准确的延迟—精度权衡分析。具体毕业认定仍以导师和学院要求为准。

**论文强结果**：M1 在两个迁移方向上稳定改善微小缺陷候选召回；M2 相对固定 K 和固定高分辨率方案形成真实 Pareto 优势，并在两种硬件上重复。

**不能声称**：若 WebGPU 比固定高分辨率方案慢，就只能称“可运行/低内存/不同精度下权衡”，不能声称“加速”。

## 六、分阶段执行与交付

### A：运行基线与实验基础（第 1—6 周，必须）

**第 1—2 周：Go/No-Go**

1. 用已有 AnomalyCLIP 权重进行离线参考推理（**非依赖项**：失败不阻塞 CLIP 学生）。
2. CLIP ViT-B/16 的 224 ONNX 模型在至少一台 WebGPU 设备运行；检测端到端时间与后端执行情况。
3. 在 PyTorch 中用最简单的全图/Oracle ROI 检测逻辑比较 Tiny/Small 子集效果。
4. 在浏览器比较 224、224 + K ROI 与可执行的 448 方案的真实时间，测试顺序/Batch。

**第 3—6 周：可复现基线**

- 构建源域训练及跨数据集评测脚本；完成多层 Patch 特征适配器、文本原型匹配头与 Patch 热力图。
- 浏览器上传图片 → WebGPU 推理 → 异常分数/热力图。
- 固定输入、导出 ONNX、验证数值一致性；产出第一组完整性能表。

**验收**：有能运行的浏览器演示、规范化数据集评测、可复现实验脚本；若基线精度不足，应先解决基础异常建模，不盲目进入动态 ROI。

### A+：核心研究（第 2—4 个月，重点）

**第 2 个月**：完成缺陷保持监督、全图/ROI 联合训练和区域排序，完成微小缺陷与 Region Recall@K 消融。

**第 3 个月**：完成候选风险定义、风险覆盖贪心选择、固定 K ROI Batch 与回投融合；比较固定网格、随机、Top-K + NMS、Oracle 与固定 K。

### 最重要的备选论文路径（粗到细失败时）

切换为：**基于 WebGPU 的缺陷保持型轻量视觉语言异常检测方法**。

研究内容：源域监督下的缺陷保持与区域排序策略 + 全图/局部一致的轻量异常头 + 浏览器 WebGPU 精度/延迟/内存分析。比较普通监督、缺陷保持监督、是否进行 ROI 联合训练、是否加入区域排序、不同局部特征组合和不同输入成本。

备选路径不再宣称自适应 ROI 加速，而将原 M1 拆成两个可独立消融的算法贡献：

1. **缺陷保持 Patch 监督**：研究高分辨率异常掩膜到低分辨率 Patch 网格的保持型映射与不均衡损失，解决微小异常监督消失问题。
2. **全局—局部尺度一致的异常对齐**：使用全图、正 ROI、难负 ROI 和正常 ROI 共享训练，并通过区域排序约束改善不同尺度下的异常语义对齐和候选排序。

浏览器端系统与分阶段实测仍作为第三项贡献。只有两个算法机制均有独立正向结果时，才采用此备选论文结构。

**边界**：此路径是否满足学术硕士创新要求，需要导师确认；若单纯标签聚合带来的提升不足，应围绕明确的特征保持或异常头设计形成实质算法贡献，而不能把网页实现算作算法创新。

此备选路径应在第 1 个月就准备实验骨架，而不是第 4 个月才从头启动。

## 八、预期创新点（必须由实验验证）

**创新点一：缺陷保持与选择导向的轻量视觉语言异常检测方法。** 针对低分辨率 Patch 监督易丢失微小异常、全图训练模型不适应局部裁剪的问题，联合缺陷保持标签聚合、全图/ROI 共享训练和区域排序约束，提高有限局部预算下的微小异常候选召回。

**创新点二：WebGPU 延迟预算约束的自适应局部细化方法。** 联合候选异常风险、空间覆盖收益、重叠惩罚和设备实测成本，以低复杂度贪心算法动态确定 ROI 集合及停止位置，改善固定计算分配的精度—延迟权衡。

**创新点三：浏览器端工业多模态异常检测系统与分阶段实测方法。** 构建无需服务端推理的浏览器闭环系统，明确神经网络计算与动态控制的执行边界，并建立覆盖加载、编译、全图、调度、裁剪上传、局部 Batch、融合及端到端延迟的可复现评价流程。

> 上述创新点是**待验证的研究贡献**，不是已经证明的首次提出。系统实现已被本课题的毕业要求认可为一项贡献，但仍需体现完整架构、关键技术问题、可复现评价和实际结果，不能仅以网页界面作为创新证据。正式论文需系统比较多尺度异常检测、动态计算、区域选择和延迟感知推理相关工作；若已有工作实现相同机制，必须进一步明确差异或调整表述。

## 九、建议的论文章节

1. 绪论：工业零样本异常检测、浏览器端部署需求、研究问题与贡献。
2. 相关技术与研究现状：CLIP/异常检测、粗到细/多尺度策略、WebGPU/ONNX Runtime Web。
3. 浏览器端轻量视觉语言异常检测基线：模型、导出、前端执行、精度与算子兼容性。
4. 面向微小缺陷的粗到细自适应异常检测方法：缺陷保持监督、候选生成、动态 ROI 与融合。
5. 实验与分析：跨数据集结果、消融、微小缺陷、真实设备延迟和 Pareto 权衡。
6. 总结与展望：有效条件、失败案例、跨设备限制、未来增强。

## 十一、一句话决策

**先做出可复现的 CLIP–WebGPU 异常检测基线；以“缺陷保持与选择导向的粗检测 + WebGPU 预算约束的局部自适应推理”形成两项算法创新，以完整浏览器系统形成第三项贡献；不确定性、蒸馏和深层内核优化全部延后。**
