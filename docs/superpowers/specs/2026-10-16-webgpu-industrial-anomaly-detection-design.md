# 基于 WebGPU 的工业多模态异常检测研究设计

日期：2026-10-16

## 1. 研究定位

论文题目确定为：

> 基于 WebGPU 的工业多模态异常检测方法

本研究不以“将现有 AnomalyCLIP 搬到浏览器”作为主要创新，而以浏览器 WebGPU 的计算与内存约束为研究条件，探索面向微小工业缺陷的自适应粗到细零样本异常检测方法。

论文的核心问题是：

> 在不使用目标域训练样本的条件下，能否利用工业异常的局部性和稀疏性，为不同图像动态分配高分辨率计算，从而在保持微小缺陷检测能力的同时降低浏览器 WebGPU 的平均推理延迟？

WebGPU 是算法的目标执行环境和优化约束，算法贡献集中于缺陷保持、候选区域排序和设备感知的动态计算分配。

## 2. 研究约束

- 论文类型：学术硕士论文。
- 可用时间：六个月。
- 当前基础：研究设想阶段，尚未完成模型复现和 WebGPU 基线。
- 训练资源假设：单张 24GB NVIDIA GPU；16GB 显存作为可降级配置。
- 目标终端：联想小新 Air-14ARE 2020 的 AMD 集成显卡，并补充至少一台 NVIDIA 独显设备。
- 研究规模：一条核心算法主线、一个浏览器验证系统、两个主要数据集。

## 3. 研究假设

研究围绕三个可证伪假设展开：

1. 局部高分辨率推理能够改善低分辨率全图推理对微小缺陷的检测和定位能力。
2. 低分辨率异常响应及其不确定性足以在有限候选数量内召回大多数异常区域。
3. 在典型 WebGPU 设备上，全图低分辨率推理加少量局部推理能够形成优于固定高分辨率全图推理的精度—延迟 Pareto 解。

任一假设不成立时，按本文规定的条件调整或终止相应研究分支，不通过继续叠加模块掩盖基础假设失败。

## 4. 研究设定

采用严格的跨数据集零样本异常检测设定。

训练阶段允许使用源域数据集的图像、图像级标签和异常掩膜；目标域的图像、正常样本、异常样本和标签均不参与训练、阈值选择、模型选择或超参数搜索。

主要跨数据集设置为：

| 设置 | 源域训练 | 目标域测试 |
|---|---|---|
| A | MVTec AD | VisA |
| B | VisA | MVTec AD |

方法参数、阈值和融合权重只在源域划分上确定。双向验证用于检查方法是否依赖某一特定源域。高分辨率数据集可作为附加测试，但不作为六个月内的硬性要求。

## 5. 总体模型结构

### 5.1 离线教师

离线教师采用 AnomalyCLIP ViT-L/14，在 518×518 输入上生成高分辨率异常响应、多层 Patch 响应和图像级异常概率。教师仅用于训练阶段，不部署到浏览器。

教师输出应预先缓存，避免学生训练期间重复执行重模型。

### 5.2 浏览器学生

浏览器学生采用 CLIP ViT-B/16 视觉编码器，输入空间尺寸固定为 224×224。模型包含轻量多层特征投影、异常语义匹配头和全局上下文门控头。只有在两周可行性验证确认 ViT-B/16 无法完整运行于目标 WebGPU 设备时，才降级为 ViT-B/32；不得在主实验中混用两个学生骨干。

ONNX 接口定义为：

```text
Inputs
├── image: [B, 3, 224, 224]
└── global_context: [B, 512]

Outputs
├── global_feature: [B, 512]
├── anomaly_map: [B, 14, 14]
├── uncertainty_map: [B, 14, 14]
└── image_score: [B]
```

正常与异常文本原型在训练完成后离线预计算并固化为模型权重，浏览器不加载文本编码器。

### 5.3 推理流程

第一次推理将整幅图像缩放到 224×224，并将 `global_context` 设为零向量。模型输出全局特征、粗异常图、不确定性图和图像级异常分数。

TypeScript 调度器根据粗异常图、不确定性和空间覆盖生成候选区域。从原始高分辨率图像裁剪候选区域并缩放到 224×224，组成局部 Batch。局部推理复用同一个学生模型，并将第一次推理得到的全局特征作为 `global_context`。

局部异常图映射回原图坐标，与粗异常图进行置信度校准和残差融合，得到最终异常图。

## 6. 候选创新结构

三项创新应形成连续算法链，而不是互不相关的技术组合。最终论文是否保留所有增强机制，由可行性验证和消融结果决定。

### 6.1 创新一：缺陷保持的跨分辨率异常知识迁移

要解决的问题是低分辨率下微小异常响应被平均或丢失。

方法首先使用缺陷保持聚合将高分辨率掩膜或教师异常图映射到学生 Patch 网格。基础实现采用最大池化；增强实现采用平滑最大聚合：

\[
\hat A_T(j)=\tau\log\left[\frac{1}{|\Omega_j|}\sum_{i\in\Omega_j}\exp\left(\frac{A_T(i)}{\tau}\right)\right].
\]

低风险版本只训练学生异常头：

\[
L_{DP}=L_{focal}(A_S,\hat Y)+L_{dice}(A_S,\hat Y).
\]

当低风险版本的区域召回不足时，增加教师软异常图蒸馏：

\[
L_{DP-CD}=L_{DP}+\lambda L_{map}(A_S,\hat A_T).
\]

这一创新的主要目标不是粗阶段精确分割，而是提高 Tiny/Small 缺陷的粗检测召回和 Region Recall@K。

### 6.2 创新二：不确定性校准的区域风险排序

要解决的问题是异常区域虽然在粗图中存在响应，但未必能进入有限的 Top-K 候选，同时异常高分也可能来自正常纹理误报。

每个候选窗口生成异常性、不确定性和异常覆盖概率：

\[
q_i=(a_i,u_i,r_i),\qquad R_i=\alpha a_i+\beta u_i+\gamma r_i.
\]

其中不确定性优先使用一次前向传播即可获得的多 Prompt 或多层预测分歧，避免 Monte Carlo Dropout 带来的重复推理。

基础版本使用确定性组合和重叠抑制。增强版本训练区域覆盖评分器，并加入排序与校准目标：

\[
L_{selector}=L_{region}+\lambda_rL_{rank}+\lambda_cL_{cal}.
\]

该创新以 Region Recall@K、Region Precision@K、Brier Score、ECE 和固定 ROI 数下的最终检测精度评价。

### 6.3 创新三：WebGPU 延迟预算驱动的自适应粗到细推理

要解决的问题是固定处理相同数量的 ROI 无法适应不同样本风险和不同终端性能。

通过目标设备实测建立离散延迟代价表：

\[
\hat T(K,d)=C_{global}(d)+C_{roi}(K,d)+C_{fusion}(K,d),
\]

其中候选数量限制为 `K ∈ {0,1,2,4,8}`，以便 WebGPU 预热和批处理。

在设备延迟预算下选择候选集合：

\[
\max_S \sum_{i\in S}R_i+\mu Coverage(S)-\eta Overlap(S),
\quad \text{s.t. }\hat T(|S|,d)\le B.
\]

当未处理区域的残余风险低于阈值时提前停止。正常且高置信样本允许 `K=0`，高风险或高不确定样本分配更多局部计算。

局部结果采用全局上下文门控和残差融合。融合首先作为第三项创新的组成部分，不单独包装为创新点。

## 7. WebGPU 实现边界

浏览器系统采用混合执行架构：

- ONNX Runtime WebGPU：执行 ViT 视觉编码器、特征投影、异常匹配和上下文门控。
- TypeScript：执行候选窗口生成、排序、重叠抑制、预算判断、坐标映射和控制流。
- Canvas/WebGPU Texture：执行原图裁剪和输入构造。
- TypeScript 或 WGSL：执行热力图插值和融合；只有性能分析证明该部分为瓶颈时才编写自定义 WGSL。

不要求把动态选择、循环和 Top-K 封装进单个 ONNX 模型。训练、教师推理和损失计算均在服务器 PyTorch 环境完成。

为降低导出风险，浏览器模型必须使用固定空间尺寸，并离线生成对应位置编码；不得保留官方实现中推理时修改位置编码参数的逻辑。

## 8. 两周可行性验证

在任何新模型训练之前，先验证三个研究假设和 WebGPU 基础兼容性。

### 8.1 范围

第一轮使用 MVTec AD 的 screw、pill、capsule、cable、tile 和 leather 六类，覆盖小缺陷、结构对象和纹理类别。按每个异常样本的掩膜面积占图像面积比例排序：不高于第 25 百分位的样本记为 Tiny，第 25 至第 50 百分位记为 Small，其余记为 Medium/Large。分组仅用于测试结果分析，不参与训练和阈值选择。

算法上界使用官方预训练 AnomalyCLIP ViT-L/14；WebGPU 性能边界使用标准 CLIP ViT-B/16 的静态 224×224 和 448×448 ONNX 模型。前者验证算法假设，后者验证部署成本，不将二者结果混为最终方法结论。

### 8.2 Oracle 局部推理上界

比较：

- 224×224 全图推理；
- 518×518 全图推理；
- 224×224 全图加一个 Oracle 局部块；
- 224×224 全图加两个 Oracle 局部块。

Oracle 使用真实掩膜确定局部块，只用于估计上界。224 和 518 模型分别使用离线生成的固定位置编码，禁止在同一模型实例中运行时修改位置编码。继续条件为：局部推理相对 224 全图在 Tiny/Small 子集上的 Pixel AP 或 AUPRO 至少提高 3.0 个百分点，并且六个类别中至少四类取得正向提升。

### 8.3 无训练区域选择

比较随机窗口、固定网格、异常分数 Top-K、Top-K 加重叠抑制、异常分数加空间覆盖，测试 `K ∈ {1,2,4,8}`。

主要指标为 Region Recall@K、Region Precision@K、异常覆盖率、窗口重叠率和最终 Pixel AP/AUPRO。继续条件为 Region Recall@4 不低于 80%，且至少比固定网格高 5.0 个百分点。

### 8.4 WebGPU 性能边界

比较单次 224、单次 448，以及 224 全图加 1、2、4、8 个 224 ROI；分别测试逐个执行和 ROI Batch。

记录模型加载、首次推理、预热后 P50/P95、模型体积、峰值内存、输出误差和执行后端。数值一致性要求 FP32 最大绝对误差不超过 `1e-3`，FP16 不超过 `1e-2`；超出时必须定位误差来源后再进行性能比较。性能继续条件为至少存在一个 `K=2` 或 `K=4` 的配置，相对固定 448 推理降低至少 30% 的稳态 P50，P95 不高于固定 448，峰值内存不超过其 1.2 倍。

### 8.5 决策规则

| 结果 | 决策 |
|---|---|
| Oracle 无明显收益 | 停止粗到细路线，重新选择核心方法 |
| Oracle 有效但粗图召回低 | 优先实现缺陷保持学习和异常图蒸馏 |
| 粗图召回高且接近 Oracle | 简化或取消复杂蒸馏，将重点转向预算分配 |
| 精度有效但 WebGPU 无加速 | 调整学生模型、Batch 和 ROI 数；仍无收益则停止路线 |
| 算法和性能均通过 | 依次实现 DP-CD、UCRR 和设备感知预算推理 |

### 8.6 两周输出

- 分辨率与小缺陷性能分析；
- Oracle 粗到细上界；
- Region Recall@K 曲线；
- ROI 数量—精度曲线；
- ROI 数量—WebGPU 延迟曲线；
- Accuracy–Latency Pareto 图；
- 继续、简化或停止各创新分支的书面结论。

## 9. 评价体系

检测指标包括 Image AUROC、Image AP、Pixel AUROC、Pixel AP 和 AUPRO。专项指标包括 Tiny/Small 缺陷召回、Region Recall@K、Region Precision@K、异常覆盖率、ECE 和 Brier Score。

系统指标包括模型加载时间、首次推理延迟、稳态 P50/P95、平均 ROI 数、吞吐量、CPU/GPU 内存和模型体积。

方法必须同时报告：

- 相同精度下的延迟；
- 相同延迟预算下的精度；
- 正常样本和异常样本各自的平均计算量；
- 不同缺陷面积区间的结果；
- PyTorch 与 WebGPU 的数值一致性。

## 10. 明确排除的范围

六个月内不将以下内容列为必要任务：

- INT8 或混合量化；
- 通用 Token Pruning；
- Embedding PCA 压缩；
- 自定义 Attention Shader；
- ONNX Runtime 内核修改；
- 大规模跨浏览器 Benchmark；
- 同时部署多个大型异常检测模型；
- 浏览器端训练。

如核心研究提前完成，可将 FP16、缓存和 IO Binding 作为工程增强，但不改变论文主线。

## 11. 风险与降级路径

### 11.1 官方 AnomalyCLIP 无法稳定导出

不导出完整官方模型。使用标准 OpenCLIP/CLIP ViT-B 视觉编码器，加自行实现的轻量异常匹配头；教师仍可离线使用官方 AnomalyCLIP。

### 11.2 24GB GPU 不可用

使用 16GB GPU，教师以 `batch_size=1` 和无梯度方式离线生成缓存；学生使用 FP16、梯度累积、Adapter 和必要的梯度检查点。

### 11.3 教师蒸馏无收益

删除教师软标签，保留源域掩膜的缺陷保持监督。第一项创新改为缺陷保持型低分辨率异常学习。

### 11.4 学习式区域排序无收益

退化为异常分数、不确定性和覆盖的确定性组合，将研究重点放到设备感知的预算分配。

### 11.5 全局上下文门控无收益

使用简单加权或最大残差融合，不把融合声明为独立创新。

### 11.6 多 ROI 推理没有延迟优势

优先尝试轻量学生、ROI Batch、离散 K 预热和更小局部分支；若仍无法形成 Pareto 优势，则停止粗到细路线，不继续投入复杂算法。

## 13. 完成标准

研究成功需要同时满足：

1. 在严格跨数据集零样本设置下，相比低分辨率基线显著改善 Tiny/Small 缺陷检测。
2. 相比固定高分辨率推理，在至少两类目标设备上形成更优的精度—延迟 Pareto 点。
3. 三个候选创新中的每个保留项均有独立动机、实现机制、消融实验和对应指标。
4. 浏览器系统能够在无服务端推理的情况下输出图像级异常分数和像素级热力图。
5. 所有主要结论来自实测 WebGPU 延迟，而不是只依赖 FLOPs 或 CUDA 时间。
